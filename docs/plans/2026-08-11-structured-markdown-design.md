# BETAv27: безопасный перевод форматированного текста

## Проблема

В BETAv26 Markdown, Patchouli-коды, XML-подобные теги и игровые идентификаторы
маскируются маркерами вида `[#0#]`. Модель всё равно видит эти маркеры и иногда
удаляет, дублирует или переставляет их. Дополнительные регулярные выражения не
могут надёжно различить все пересекающиеся конструкции: например, экранированные
звёздочки, `GUI` внутри `gui`, цвет `$(#ED7014)` и вложенные ссылки.

## Решение

BETAv27 вводит отдельный lossless-модуль форматированного текста. Он разбирает
исходную строку на две категории:

- неизменяемые фрагменты: Markdown-разметка, ссылки, теги, Patchouli-команды,
  цветовые коды, placeholders и игровые идентификаторы;
- обычный видимый текст, который разрешено переводить.

В движок перевода передаются только текстовые узлы. Неизменяемые фрагменты модель
не видит, а итоговая строка собирается из оригинальных фрагментов программно.
Поэтому модель физически не может повредить ссылку, цвет, тег или управляющий код.

## Архитектура

- `mineai/formats/rich_text.py` — единый lossless-токенизатор и сборщик.
- `mineai/formats/markdown.py` — `MarkdownSkeleton`, адаптер Markdown-книг и
  проверки структуры документа. Skeleton хранит точные исходные разделители
  строк и является единственной точкой сборки документа.
- `TranslationService.translate_formatted_dict()` — перевод только текстовых
  узлов с контекстным ключом кэша.
- `JarProcessor` использует этот путь для Markdown и JSON-книг и явно выбирает
  книжный промпт.
- LM Studio получает JSON-режим только для пакетных запросов, где ожидается JSON.

## Инварианты безопасности

1. `render(parse(source)) == source` побайтно для поддерживаемого текста.
2. В запросе к ИИ отсутствуют исходные Markdown/Patchouli-токены и служебные
   маркеры `[#N#]`.
3. Любой неизменяемый фрагмент в результате совпадает с оригиналом, потому что
   он не переводится и не восстанавливается моделью.
4. Если перевод текстового узла пытается добавить разметку, узел отклоняется и
   сохраняется безопасный исходный текст.
5. Один и тот же короткий текст на разных страницах не склеивается кэшем без
   учёта файла и узла.
6. `MarkdownSkeleton.render(original_lines)` возвращает исходный документ
   побайтно, включая смешанные `CRLF`, `LF`, `CR` и завершающий перенос.
7. Обычные lang JSON не проходят через книжный tokenizer; JSON-книги и Markdown
   используют один форматированный путь.

## Совместимость

Обычные языковые JSON модов остаются на существующем быстром пути. Новый путь
включается для книжного форматированного содержимого и одинаково применяется к
LM Studio, KoboldCpp и Google/fallback, поскольку разбор выполняется до выбора
движка, а сборка — после него.
