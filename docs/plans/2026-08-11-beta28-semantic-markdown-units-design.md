# BETAv28: смысловые единицы Markdown

## Цель

Не отправлять переводчику оборванные физические строки, сохранив детерминированную
lossless-сборку Markdown из BETAv27 для всех движков перевода.

## Решение

Планировщик Markdown объединяет только соседние обычные текстовые строки одного
абзаца. Границы синтаксических блоков не пересекаются. Полученный абзац проходит
через общий tokenizer игровых кодов; LM Studio, KoboldCpp или Google получают
только его видимые текстовые узлы.

Переведённый абзац распределяется по исходному числу строк на границах слов
пропорционально длине исходных фрагментов. Оригинальный skeleton возвращает
разделители строк и проверяет структуру. Если распределение невозможно, исходный
абзац восстанавливается целиком.

## Границы объединения

Не объединяются заголовки, списки, цитаты, YAML, таблицы, строки с жёстким
переносом, а также строки, содержащие Markdown-разметку или игровые коды. Для них
действует обычный lossless-tokenizer BETAv27.

## Единообразие движков

Группировка выполняется до выбора движка, а проверка результата — в общем
`TranslationService`. Поэтому правила одинаковы для LM Studio, KoboldCpp,
прямого Google Translate и Google fallback.
