# BETAv21: провайдер LM Studio

## Решение

LM Studio добавляется как самостоятельный AI-провайдер. В главном списке
движков появляется пункт `LM Studio`, а в окне настроек — отдельная вкладка с
адресом сервера, необязательным API-токеном и выбираемой моделью.

Адрес по умолчанию — `http://localhost:1234/v1`. Программа обращается к
OpenAI-совместимым endpoint'ам `/v1/models` и `/v1/chat/completions`. Она не
запускает LM Studio и не требует путь к GGUF: Local Server пользователь включает
в самом LM Studio.

Вкладка позволяет обновить список моделей и проверить соединение, не блокируя
интерфейс. Если сохранённая модель доступна, выбор сохраняется; если модель ещё
не выбрана, используется первая найденная текстовая модель. Пустой список
считается работающим сервером без доступных моделей и показывается отдельно.

Для ускорения последовательных запросов LM Studio использует один
`requests.Session`, поэтому TCP-соединение переиспользуется. Пакетирование,
кэширование, дедупликация, проверки маркеров и повторные попытки остаются
прежними — качество и защита форматов не ослабляются. Параллельные запросы к
одной локальной модели не включаются, чтобы не ухудшить скорость и не увеличить
расход VRAM.

## Проверка

- Конфигурация получает безопасные значения LM Studio по умолчанию.
- Адрес нормализуется до OpenAI-compatible base URL.
- Список моделей читается через `/v1/models`, токен передаётся только когда задан.
- Chat Completions содержит выбранную модель и использует постоянную HTTP-сессию.
- Отмена задания корректно прерывает повторные попытки без ложной сетевой ошибки.
- LM Studio не запускает KoboldCPP и не требует локальный файл GGUF.
- Вкладка настроек сохраняет URL, токен и модель.
- Полный набор тестов проходит; версия повышена до BETAv21; EXE собирается.
