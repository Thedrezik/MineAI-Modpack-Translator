# Beta39: журнал и обнаружение моделей LM Studio

## Цель

Beta39 улучшает наблюдаемость работы без изменения конвейера перевода. Журнал
должен сохранять полный диагностический текст, позволять безопасно переключаться
между компактным и полным представлением и защищать пользователя от случайной
очистки. Настройки LM Studio должны выбирать именно уже загруженные LLM, а не
произвольные скачанные модели.

## Журнал

- `mineai_log.txt` получает явную границу каждого запуска приложения и временную
  метку для каждой записи. В интерфейсе текст остаётся чистым и пригодным для
  поиска.
- В `LogEntry` всегда хранится полное исходное сообщение. Компактный режим строит
  только временный preview и не изменяет сохранённую запись.
- Флаг «Полные строки» отключает любое сокращение, включая сообщения об
  отклонённых переводах. Перенос по ширине окна остаётся включённым, поэтому весь
  текст доступен без горизонтальной прокрутки.
- Корзина рядом с экспортом очищает только журнал текущего окна. Перед очисткой
  показывается подтверждение с безопасным ответом «Нет» по умолчанию. AI-кэш,
  Google-кэш и импортированные кэши не изменяются.

## LM Studio

- Кнопка «Обновить модели» сначала обращается к официальному
  `GET /api/v1/models` и извлекает LLM из `loaded_instances`.
- Если загружен один экземпляр, его `id` автоматически устанавливается в поле
  модели. Если экземпляров несколько, комбобокс содержит только их ID и
  пользователь выбирает нужный.
- Embedding-модели и незагруженные модели не предлагаются.
- Для LM Studio старее 0.4 применяется совместимый fallback к `/api/v0/models`
  с фильтром `state == "loaded"`. Если сервер вообще не предоставляет состояние,
  ID остаётся доступен для ручного ввода: незагруженная модель автоматически не
  выбирается.

## Проверка

Регрессионные тесты подтверждают полный текст, подтверждение очистки, формат
файлового журнала и выбор одного/нескольких загруженных ID. После реализации
выполняются полный pytest, compileall, проверка diff и сборка EXE Beta39.
