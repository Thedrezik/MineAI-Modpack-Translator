# Выбор элементов после анализа

## Цель

После завершения анализа пользователь получает отдельный список найденных модов, книг и квестов. Каждый элемент включён по умолчанию. Снятая галочка должна исключать элемент одновременно из оценки объёма и из фактической обработки; исходные и целевые файлы такого элемента не открываются для записи.

## Модель данных

Элемент анализа содержит отображаемые поля, статистику и стабильный ключ из нормализованного абсолютного пути и области: `mods`, `books` или `quests`. Один JAR может создать две строки: интерфейс мода и объединённые книги. Благодаря разным областям их можно включать независимо. SNBT, BetterQuesting и внешние JSON-словари представлены отдельными строками.

Набор выбранных ключей добавляется в `TranslationOptions`. Значение `None` означает, что анализ не использовался и действует прежнее поведение «обработать всё в выбранных верхних категориях». Пустой набор после анализа означает, что пользователь снял все галочки, поэтому запуск блокируется.

## Интерфейс

Между карточкой текущей задачи и журналом появляется скрытая карточка результатов анализа. При поступлении первого элемента она показывается. Таблица содержит галочку, название, тип и готовность перевода, а также действия «Выбрать всё» и «Снять всё». При повторном анализе или смене папки прежний список сбрасывается. Во время фоновой работы список блокируется.

## Поток выполнения и безопасность

Анализатор передаёт в GUI структурированный элемент параллельно с прежней строкой журнала. Перед оценкой и обработкой `TranslationJob` фильтрует файлы по выбранным ключам. Для JAR отдельно вычисляются разрешения на интерфейс и книги и те же разрешения передаются оценщику и процессору. Это исключает расхождение прогресса с реальной работой.

Обратная совместимость сохраняется: старые вызовы `TranslationOptions` без выбора продолжают переводить всё. Выбор не сохраняется между разными Minecraft-папками, чтобы устаревшие пути не могли случайно управлять новой сборкой.

## Проверка

Регрессионные тесты должны доказать, что снятая область JAR не передаётся процессору, невыбранный квест не обрабатывается, оценщик получает тот же выбор, а список GUI создаёт отмеченные по умолчанию элементы и возвращает только оставленные галочки.
