# Beta38: усиление конвейера перевода

## Причины

Логи показали четыре независимых источника отказов: отправку числовых значений
переводчикам, перестановку FormatKit-якорей моделью, ложный подсчёт `[` внутри
`[#N#]` и обработку готовых Oracle Index переводов как английских источников.

## Решение

1. Общий tokenizer маскирует числовые фрагменты до вызова любого движка.
   Значения без переводимого текста завершаются локально как identity.
2. `translate_formatted_dict` отправляет одним пакетным запросом отдельные
   видимые части `RichTextTemplate`. Неизменяемые части никогда не покидают
   программу и возвращаются методом `render`.
3. Валидатор повторно токенизирует готовый кандидат и сравнивает точную
   последовательность защищённых фрагментов вместо поиска пересекающихся
   подстрок.
4. Oracle Index отбрасывает `.translated/*` и `translated/*` до построения
   плана.
5. Анализ собирает типы фактически выбранных адаптеров и показывает их в
   журнале и диалоге выбора.
6. Известные стандартные промпты прошлых версий мигрируют на новый контракт;
   произвольный пользовательский текст не заменяется.

## Критерии приёмки

- числа и numeric-unit значения не достигают AI/Google;
- no-op и переведённая реконструкция не меняют скелет документа;
- пробелы между чанками сохраняются;
- иностранные деревья Oracle Index не создают единиц перевода;
- полный набор тестов и корпус всех локальных сборок проходит без ошибок.
