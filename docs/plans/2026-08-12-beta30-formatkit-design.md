# Beta30 FormatKit design

## Решение

FormatKit — встраиваемая библиотека без доступа к файловой системе, архивам,
GUI, кэшу и сетевым переводчикам. Вызывающее приложение передаёт библиотеке
логический путь и декодированный исходный английский текст. FormatKit выбирает
адаптер, возвращает точный план перевода, применяет полученные payload и
доказывает сохранность структуры. MineAI по-прежнему отвечает за поиск файлов,
выбор пользователя, чтение JAR/ZIP, LM Studio/Google и запись результата.

## Публичный контракт

- `FormatRegistry.plan(logical_path, source_text, target_locale)` выбирает
  адаптер и возвращает `TranslationPlan`.
- `TranslationPlan.units` содержит `TranslationUnit`: стабильный ID, payload,
  контекст, точные исходные диапазоны и метаданные.
- В payload нет настоящих Minecraft-тегов, ссылочных адресов, цветов и кодов.
  Вместо них используются проверяемые якоря FormatKit. Это даёт переводчику
  контекст целого предложения, но не позволяет изменить защищённую разметку.
- `TranslationPlan.apply(translations)` восстанавливает исходные токены,
  возвращает target-текст и `ValidationReport`.
- `target_path` является рекомендацией адаптера. Приложение решает, куда и как
  записать результат.

## Адаптеры Beta30

1. GuideME Markdown: `_ru_ru`, front matter, заголовки, абзацы, списки,
   Markdown-ссылки, таблицы, изображения, HTML/MDX, `ItemLink`,
   `ImportStructure`, сцены и точные переносы.
2. Immersive Engineering manual: `<link;...>`, `<&...>`, `<np>`, `<br>`,
   коды `§`, переводимые подписи ссылок и зависимости
   `manual.immersiveengineering.*`.
3. Generic Markdown: безопасный запасной адаптер для остальных
   `.md`/`.markdown`/`.txt`.
4. Properties: локализованные `.lang` с неизменяемыми ключами, разделителями,
   комментариями и переносами.
5. XML text: перевод только текстовых узлов с неизменяемыми тегами,
   атрибутами и entities.
6. JSON и SNBT продолжают использовать существующие структурные процессоры в
   Beta30, но получают тот же контракт план/применение через совместимый bridge.
   Их полный лексический перенос в независимый пакет выполняется отдельно,
   чтобы не менять квестовые форматы без реальных регрессионных образцов.

## Доказательство сохранности

- no-op round-trip возвращает исходный текст байт-в-байт;
- диапазоны единиц не пересекаются и полностью проверяются;
- набор и порядок защищённых якорей обязан совпасть;
- неизменяемые участки сравниваются с английским оригиналом;
- результат повторно разбирается тем же адаптером;
- GuideME дополнительно проверяет относительные ссылки и использует корректный
  локализованный page ID;
- для относительных `src`/`href` и Markdown-ссылок FormatKit вычисляет
  замыкание нетекстовых зависимостей. Приложение копирует только реально
  существующие ресурсы в путь, который получится после переноса документа;
- при ошибке отдельного payload применяется fail-closed для этой единицы:
  корректные переводы сохраняются, повреждённая единица возвращается к
  английскому оригиналу, а причина попадает в журнал и запись кэша удаляется.

## Интеграция MineAI

Анализатор, estimator и JarProcessor обязаны получать единицы из одного и того
же `TranslationPlan`, поэтому число строк и фактическая обработка совпадают.
TranslationService переводит payload единиц целиком. Пустой перевод допустим
для английских артиклей и притяжательных суффиксов, если адаптер пометил их как
грамматический узел. Кэш привязывается к adapter ID, пути, unit ID и hash
английского источника, чтобы старые фрагментированные ответы Beta29 не
переиспользовались.

Обнаружение форматов не зависит от mod ID. Явный сегмент `/en_us/` определяет
локализованный JSON, `.lang` и XML. Markdown без сегмента locale допускается
только внутри каталога с документным назначением. Это отделяет книги от
word-list и служебных `.txt`, перевод которых способен изменить игровую
логику. Обычные loose-словари обнаруживаются по форме
`config/<namespace>/lang/en_us.json`; при ресурспак-выводе namespace задаёт
путь `assets/<namespace>/lang/<locale>.json`.

Loose-контент под `kubejs/assets` использует те же правила, что содержимое
JAR. Файл внутри `/en_us/` считается отдельной локализованной книгой, а не
плоским словарём. JSON-адаптер выбирает поля по семантике ключа и рекурсивно
обходит контейнеры: внешний `text` не скрывает внутренние `text`-абзацы.
